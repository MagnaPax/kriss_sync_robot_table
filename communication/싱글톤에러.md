# `QObject`를 상속받는 싱글톤은 시한폭탄과 같다

---

### 💥 1. `test_turntable.py` 실행 시 사망 과정 (싱글톤일 때)

사용자님이 `python -m communication.test_turntable`을 엔터 치는 순간, 다음과 같은 일이 벌어졌습니다.

1.  **[0.0초] 파이썬 시작:**
    * 스크립트 파일(`test_turntable.py`)을 위에서부터 읽기 시작합니다.
2.  **[0.1초] Import 만남:**
    * `from core.event_bus import EVENT_BUS` 코드를 만납니다.
3.  **[0.2초] 싱글톤 작동 (재앙의 시작):**
    * 파이썬이 `EventBus` 클래스를 읽습니다.
    * 파일 맨 끝에 있는 `EVENT_BUS = EventBus()` 줄을 실행합니다.
    * **싱글톤(`__new__`)** 특성상, "나를 부르면 무조건 즉시 객체를 만들어낸다"는 원칙이 발동합니다.
4.  **[0.3초] Qt 시스템 호출:**
    * `EventBus`는 `QObject`입니다. 태어나면서 운영체제(Qt)에게 **"나 태어났어! 등록해줘!"** 하고 외칩니다.
5.  **[0.4초] 사망 (Silent Crash):**
    * 운영체제(Qt): **"뭐야? 아직 `QApplication`(앱/건물)도 안 지어졌는데 누가 입주 신고를 해?"**
    * **메모리 충돌(Segmentation Fault) 발생.**
    * 파이썬은 "으악!" 소리도 못 지르고 그 자리에서 즉사합니다. (이게 로그도 없이 꺼지는 이유입니다.)
6.  **[...이후]**
    * `test_turntable.py` 안에 있는 `app = QCoreApplication()` 코드는 실행될 기회조차 얻지 못했습니다.

---

### ❓ 왜 싱글톤이 문제였나?

싱글톤 패턴 자체가 나쁜 것은 아닙니다. 하지만 **PyQt(GUI 프로그래밍)에서의 싱글톤**은 아주 위험합니다.

* **일반적인 싱글톤:** "언제 어디서든 하나만 존재한다." (좋음)
* **우리가 썼던 싱글톤:** **"프로그램이 켜지자마자(Import 하자마자) 무조건 태어난다."** (위험)

`QObject`는 반드시 **`QApplication`이 만들어진 뒤(After)**에 태어나야 하는데, 싱글톤 로직이 **`QApplication`보다 먼저(Before)** 태어나려고 새치기를 했기 때문에 죽은 것입니다.

---

### ✅ 우리가 수정한 방법 ("게으른" 방식)

우리가 `Proxy(대리자)`를 써서 고친 방식은 **"게으름(Laziness)"** 전략입니다.

1.  **[0.1초] Import 만남:**
    * `EVENT_BUS`를 부릅니다.
2.  **[0.2초] 껍데기만 등장:**
    * `EventBus`인 척하는 **가짜(Proxy)**가 나갑니다. 얘는 `QObject`가 아니라서 Qt랑 상관없습니다. (안 죽음)
3.  **[1.0초] `test_turntable.py` 실행:**
    * 드디어 `app = QCoreApplication()`이 실행됩니다. **(건물 완공 🏗️)**
4.  **[2.0초] 실제 사용:**
    * 코드 어딘가에서 `EVENT_BUS.emit()`을 합니다.
5.  **[2.1초] 진짜 생성:**
    * 가짜(Proxy)가 "이제 건물 다 지어졌네? 진짜 데려오자." 하고 `EventBus`를 만듭니다.
    * 이때는 건물이 있으니까 Qt가 기쁘게 받아줍니다. **(성공 🎉)**
